# V5: frozen multi-entity diagnostic

This study evaluates existing fixed checkpoints. It has no training, checkpoint selection, architecture change, or temperature fitting. Scientific source, settings, input hashes, model files/revisions, and this document are sealed before GPU scoring. Preparation and a separate timing pilot are authorized by the owner on 2026-10-13.

## Models and data

Compare the private pinned V3 treatment-final, V4 changed-premise control, and V4 mixed-data releases recorded in `configs/v5.yaml`. Use their stored temperatures, class order TRUE/FALSE/UNKNOWN, 512-token limit, and existing head architecture. Scoring uses BF16 CUDA autocast; fixed artifact reference verification uses FP32. Tokenization rejects overlength families instead of truncating input.

Dataset seed 521. Diagnostic: 288 conjunction families, 96 deeper families, and 96 signed-chain families. Separate pilot: 12 families per suite. Every family has three entities and nine variants, with three independently scored queries per variant: 27 inputs. Total: 12,960 diagnostic and 972 pilot inputs. Scoring three models produces 38,880 diagnostic prediction rows, not independent families.

Every base world supports one TRUE, one FALSE, and one UNKNOWN query about the same predicate. Every entity has three explicit facts, blocking a simple per-entity occurrence-count shortcut. Conjunction and deeper worlds share the first premise across all entities; deeper proofs have depth 3–4, ordinary conjunction and signed-chain proofs depth 1–2. Signed chains have separate universal rules for both polarities with one condition per rule; they are not claimed to reproduce the earlier single-branch distribution. Predicate vocabulary and entity names come from the original generator. Diagnostic names, query slots, and query polarity are exactly balanced within each suite. Pilot inputs need not have that balance and are not scientific endpoints.

Variants: base; consistent cyclic renaming; reversed fact/rule order and changed query execution order; irrelevant facts using disjoint predicates; negated queries; paraphrased rule wording; remove support for the initially TRUE entity; reverse that entity's support; repair the initially UNKNOWN entity. Semantic edits change only one entity's answer, preserving the other two. Remove/reverse/repair conditions have intentionally different label proportions from the balanced base worlds. Each query is a separate model input; there is no conversation or preceding answer in context.

All variants stay in their parent family. Canonical worlds exclude all available V1–V4 registries and cannot cross pilot/diagnostic or different parent families. Production forward chaining and a separate synchronous fixed-point implementation must agree on closures and query labels. Serialized facts, rules, prompts, labels, hashes, and expected intervention locality are audited again before freezing. The independent implementation shares schema/grounding utilities and is not a wholly independent parser. Proof closures are retained in the family registry.

## Endpoints and analysis

Primary descriptive endpoint: V4 mixed-model complete-base-world accuracy in the 288 conjunction families, meaning all three queried entities receive their correct different answers. Report its parent-family bootstrap percentile 95% interval with 2,000 resamples, seed 521. There is no pass/fail threshold or claim of a training-treatment effect in this diagnostic.

For every model/suite/variant, report accuracy, actual-row confusion matrix, class counts, macro F1, raw and saved-temperature NLL/ECE/Brier, confident wrong answers at probability >=0.9, complete-world correctness, and worlds receiving one constant prediction. Report query-only pairs: prediction changes and both answers correct. For label-preserving transformations, report invariance and both correct separately. For premise edits, report target changes and both correct, and unaffected-entity prediction invariance and both correct. Negation equivariance follows TRUE/FALSE exchange and UNKNOWN preservation.

Descriptive paired contrasts: V4 mixed minus V3 parent and V4 mixed minus V4 control in complete-base-world correctness, resampling corresponding parent families. Transfer metrics/contrasts are not multiplicity-adjusted hypothesis tests. Intervals describe test-family sampling for these fixed models; there is no training-seed replication. A collapsed empirical interval is not proof of perfect population performance. Always-TRUE and any other constant-world predictor achieve one-third base accuracy and zero complete-world accuracy; name-only and query-slot-only labels are balanced.

Preselected numerical examples: the first diagnostic family in each suite (`000000`), fixed before inference. Retain them whether they succeed or fail. These examples illustrate behavior and do not replace aggregate evidence. Follow-up error analyses must be labeled post-test and cannot change these endpoints.

## Limits and operations

The three-entity unary world generator is deliberately small. All three labels always co-occur; fillers or missing branch premises can offer shortcuts. It tests behavioral consistency and known rule-depth/wording transfer, not an internal reasoning mechanism or unrestricted decisions. Balanced names and fact counts remove specific easy cues without proving absence of all cues. Prior canonical exclusion does not establish disjoint abstract rule structures. A positive result requires a separate harder study before claiming broad generalization.

One L4, four physical CPU cores, 32 GiB RAM; one container, zero automatic retries, two-second scale-down. Timeouts: pilot 300s, diagnostic 1,200s; startup 180s.
